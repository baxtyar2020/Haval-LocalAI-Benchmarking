How judgment and scores are decided

Scoring is a funnel. We do not average a slow disaster with a pretty paragraph and call it a win.

  1. Did it finish? If it never produced an answer, that is Failed — not “slow.”
  2. Was it far too slow for that role? If yes, it is Not recommended even if the text looks excellent.
  3. Combined score. About half is everyday role work (Phase 1). About half is a skill pack (Phase 2). Skills are weighted by the role — an engineer needs coding; a family coordinator does not.
  4. Role floors. Some jobs refuse a label if a required skill is too weak.
  5. Final match label from the scale below.

The funnel

Excellent 88 and up
Strong 75–87
Acceptable 62–74
Marginal match 48–61
Not recommended below 48, or blocked by speed / a role floor
Failed no usable finish

Size is not the winner. Fit is.

How the app is put together (short)

You see one window. On this PC, helpers work together locally:

The screens

Home, Doctor, Models, Benchmark, Reports, Compare, Settings.

The engine

Local helper that runs Doctor, scores answers, and writes HTML reports.

Ollama

Local model server. It generates answers. It does not grade them.

Your files

Settings, history, and reports stay under this Windows user account.

Click → screens ask the engine → the engine asks Ollama for text → this PC grades the text → a report is saved.
